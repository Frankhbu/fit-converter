# fit-converter 工程目录与数据流说明

本文记录 `fit-converter` 的目录约定、各目录含义，以及各子命令的数据流向与默认路径。
所有路径均相对于仓库根目录（脚本与程序默认的工作目录）。

## 一、总体约定

- `input/` —— 只读输入。按「用途 / 数据来源」两级划分（出于隐私考虑，仓库不附带真实数据，目录需自行创建）。
- `output/` —— 全部程序产物。按「数据集（sample / real）/ 产物类型」两级划分（已 gitignore）。
- `src/`、`tools/`、`pom.xml` —— 代码、脚本与构建配置。
- 华为健康 App 导出的原始数据包 —— 保存在工程目录之外，不复制进 `input/`，通过 `export` / `split` 子命令的参数指定路径。

## 二、输入目录 `input/`

| 路径 | 内容 |
| --- | --- |
| `input/sample/huawei/` | 华为样本 JSON，文件名 `sportType_<code>_<中文名>.json`，**一个文件一条运动记录** |
| `input/sample/garmin/` | 佳明官网下载的真实 FIT 文件，作为字段对照基准 |

样本可覆盖的运动类型：1 爬楼、3 骑行、4 户外跑步、5 户外步行、101 室内跑步、
117 自由训练、118 越野跑、140 力量训练、281 室内步行、283 跳绳。

真实整包输入不放在 `input/` 下，而是直接从华为健康导出数据包中读取
`Motion path detail data & description/motion path detail data.json`，
路径通过 `export` / `split` 子命令的参数指定。

## 三、输出目录 `output/`

### 3.1 样本数据集 `output/sample/`

| 路径 | 内容 |
| --- | --- |
| `output/sample/garmin_fit/` | 由华为样本 JSON 转换出的 FIT，文件名与输入 JSON 同名 |
| `output/sample/huawei_json/` | 样本 JSON 解析后重新序列化的 JSON，用于无损校验 |
| `output/sample/csv/huawei/` | 本项目产物 FIT 的 FitCSVTool 导出（`.csv` + `.log`） |
| `output/sample/csv/garmin/` | 佳明真实 FIT 的 FitCSVTool 导出（`.csv` + `.log`） |

`garmin_fit` 的命名含义是「按佳明 FIT 规范产出的文件」，与 `csv/huawei`（我方产物导出）
和 `csv/garmin`（佳明原始文件导出）配对使用，便于逐消息、逐字段对照。

### 3.2 真实数据集 `output/real/`

| 路径 | 内容 |
| --- | --- |
| `output/real/fit/` | 华为健康导出整包记录转换出的 FIT，文件名 `开始时间_运动类型中文名.fit` |
| `output/real/json/` | 华为健康导出整包拆解出的单活动 JSON，文件名 `开始时间_运动类型中文名.json` |

### 3.3 `output/` 根目录下的分析文件

| 文件 | 说明 |
| --- | --- |
| `compare_report.txt` | 原始 JSON 与重序列化结果的字段级差异报告 |
| `compare_session.txt` | 我方 FIT 与佳明 FIT 的 session 消息对照记录 |
| `improvement_plan.md` | 字段对照后整理出的改进事项 |
| `simplify_dump.txt` | 华为 SIMPLIFY 汇总字段的原始内容转储 |

## 四、子命令与数据流

总入口 `me.frankhbu.fitconverter.Main`，用法：

```
java -jar fit-converter.jar <子命令> [源] [输出目录]
```

| 子命令 | 实现类 | 默认输入 | 默认输出 |
| --- | --- | --- | --- |
| `convert` | `convert/ConvertToFit` | `input/sample/huawei` | `output/sample/garmin_fit` |
| `export` | `convert/ConvertExportJson` | 华为导出数据包整包 JSON（需参数指定） | `output/real/fit` |
| `parse` | `parser/ParseToJson` | `input/sample/huawei` | `output/sample/huawei_json` |
| `split` | `parser/SplitToJson` | 华为导出数据包整包 JSON（需参数指定） | `output/real/json` |
| `compare` | `compare/CompareJson` | `input/sample/huawei` | `output/sample/huawei_json` |

数据流向：

```
input/sample/huawei/*.json ──convert──> output/sample/garmin_fit/*.fit
                           ──parse────> output/sample/huawei_json/*.json
                           ──compare──> 与 output/sample/huawei_json 逐字段比对

华为导出数据包整包.json ──export──> output/real/fit/*.fit
                          ──split───> output/real/json/*.json

output/sample/garmin_fit/*.fit ──┐
                                 ├─export_csv.sh──> output/sample/csv/{huawei,garmin}/
input/sample/garmin/*.fit ───────┘

output/real/fit/*.fit ──check_real.sh──> FitCSVTool 合法性校验（临时产物在 /tmp）
```

`convert` 与 `export` 的区别：
- `convert` 处理「一个 JSON 一条记录」的样本文件，输出文件名与输入同名，便于与佳明基准对照。
- `export` 处理「一个 JSON 含多条记录」的原始导出整包，输出文件名为 `开始时间_运动类型中文名.fit`。
- `split` 同样处理原始导出整包，但不转 FIT，而是把每条记录原样拆解为独立 JSON 文件（`attribute` 原始字符串无损保留），输出到 `output/real/json/`。

## 五、辅助脚本 `tools/`

| 脚本 | 作用 |
| --- | --- |
| `tools/export_csv.sh` | 用 FitCSVTool 把样本产物 FIT 与佳明基准 FIT 分别导出为 CSV |
| `tools/check_real.sh` | 对 `output/real/fit` 下全部 FIT 跑 FitCSVTool，统计退出失败与日志告警数量 |

两个脚本均内置 `cd "$(dirname "$0")/.."`，可从任意目录执行。
FitCSVTool 位于 `libs/FitCSVTool.jar`。

## 六、编译

使用 Maven 构建（FIT SDK 通过中央仓库依赖 `com.garmin:fit`）：

```bash
mvn clean package
java -jar target/fit-converter.jar convert
```
