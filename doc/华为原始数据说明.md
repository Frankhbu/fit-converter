# 华为原始数据说明

本文档说明华为运动健康导出的原始数据包（出于隐私考虑未随仓库发布），以及它们与转换项目的关系。

## 一、数据包总览

导出内容包含两个数据包，来源不同、用途不同：

| 数据包 | 来源 | 大小 | 用途 |
| --- | --- | --- | --- |
| `HUAWEI_HEALTH_<导出时间戳>` | 华为运动健康 App 主包 | 约 324 MB | **转换项目唯一使用的数据源** |
| `HUAWEI_HEALTHKIT_<导出时间戳>` | 第三方 App 经 HealthKit 写入的数据 | 约 28 KB | 与本项目无关，仅作留存 |

> 结论：把华为运动数据转成佳明 FIT，只用 App 主导出包 `HUAWEI_HEALTH_<导出时间戳>`。

## 二、主包内部结构

主包 `HUAWEI_HEALTH_<导出时间戳>/` 下按「数据 + 字段说明」成对组织，每个子目录都包含一个 `.json` 数据文件和一个 `-Data Field Description.xlsx` 字段说明表：

| 子目录 | 数据文件 | 大小 | 内容 |
| --- | --- | --- | --- |
| `Health detail data & description` | `health detail data.json` | 约 279 MB | 健康明细（最大，含心率等） |
| `Sport per minute merged data & description` | `sport per minute merged data.json` | 约 24 MB | 逐分钟运动合并数据（户外步行/跑步的分钟级拆分） |
| `Motion path detail data & description` | `motion path detail data.json` | 约 23 MB | 运动记录（含 GPS 轨迹、指标序列、纯汇总三类） |
| `Sample sequence data & description` | `sample sequence data.json` | 约 1.4 MB | 采样序列数据 |
| `User route data & description` | `user route data.json` | 约 333 KB | 用户路线数据 |
| `User int plan data & description` | — | — | 用户智能计划 |
| `User int run plan data & description` | — | — | 用户智能跑步计划 |
| `User run plan data & description` | — | — | 用户跑步计划 |
| `SportsHealth data & desciption` | 多个 `.xls` | — | 运动健康杂项（用户信息、购买、课程等 70+ 张表） |

## 三、运动记录全貌（有轨迹 + 无轨迹）

运动记录集中在两个文件：

### 1. `Motion path detail data.json`（226 条正式运动记录，2023-12-17 ~ 2024-07-28）

按轨迹情况分三类：

| 类别 | 条数 | 说明 |
| --- | --- | --- |
| GPS 轨迹 | 127 | 有经纬度点（`lbs`），可还原真实路线 |
| 指标序列（无 GPS） | 86 | 只有心率/步频/步数等指标，无经纬度 |
| 纯汇总（无轨迹） | 13 | 只有总时长/卡路里/步数，无任何轨迹点 |

按运动类型明细：

| 运动类型 | 次数 | GPS轨迹 | 指标序列 | 纯汇总 | 距离(km) | 时长(h) | 卡路里(kcal) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 户外步行 | 92 | 91 | 1 | 0 | 254.62 | 47.3 | 16538 |
| 室内跑步 | 42 | 0 | 42 | 0 | 287.68 | 27.9 | 18059 |
| 爬楼 | 24 | 0 | 24 | 0 | 0 | 16.4 | 9121 |
| 户外跑步 | 20 | 15 | 5 | 0 | 158.74 | 16.9 | 11720 |
| 骑行 | 20 | 20 | 0 | 0 | 79.79 | 5.8 | 2052 |
| 跳绳 | 16 | 0 | 3 | 13 | 0 | 1.4 | 797 |
| 室内步行 | 5 | 0 | 5 | 0 | 11.33 | 2.4 | 370 |
| 力量训练 | 5 | 0 | 5 | 0 | 0 | 1.9 | 583 |
| 越野跑 | 1 | 1 | 0 | 0 | 36.46 | 5.7 | 3679 |
| 自由训练 | 1 | 0 | 1 | 0 | 0 | 0.1 | 54 |

关键结论：

- **"室内跑步"其实有轨迹详情**——只是没有 GPS 经纬度（`lbs` 点），但有完整的心率（`h`）、步频（`s`）、步数（`rs`）等指标序列。属于"无 GPS 轨迹"，而非"完全无轨迹"。
- **真正完全无轨迹的只有跳绳**（13 条），`attribute` 里是 `HW_EXT_TRACK_DETAIL@is0`（轨迹为空），只有总时长/卡路里/步数。
- GPS 轨迹点用 **GCJ02 火星坐标**（`coordinate` 字段 = `"GCJ02"`），转佳明 FIT 时需注意坐标系差异。

| 运动类型 | sportType | 分钟数 | 距离(km) | 卡路里 | 步数 |

| 户外跑步 | 4 | 7670 | 1009.2 | 72801031 | 1239166 |
| 登山 | 2 | 1889 | 101.5 | 11011731 | 133115 |
| 健身 | 10 | 1549 | 0.0 | 8123325 | 8 |
| 骑行 | 3 | 299 | 70.5 | 2000717 | 2999 |
| 深睡 | 6 | 331 | 0.0 | 0 | 0 |
| 浅睡 | 7 | 305 | 0.0 | 0 | 0 |

> 说明：`sport per minute` 里出现的 `6（深睡）`、`7（浅睡）` 是睡眠类型，距离/卡路里/步数全为 0，**不是运动，不应转换**。`2（登山）`、`10（健身）` 是真实运动类型，但仅存在于这份无 GPS 轨迹的逐分钟数据里；本项目维持只转换有 GPS 轨迹的 `Motion path detail data.json`，故这两类当前无转换入口。

## 四、关键数据结构（转换所需）

### 1. 运动详情 `HuaweiSportDetail`

- `hasTrackPoint`：标识是否有轨迹点。
  - `false`：无轨迹运动，数据在 `Sport per minute merged data.json`。
  - `true`：有轨迹运动，轨迹详情在 `HwExtTrackDetail`。

### 2. 轨迹详情 `HwExtTrackDetail`

轨迹点存在 `attribute` 字段里，格式：`HW_EXT_TRACK_DETAIL@` 开头，分号分隔，每个点 `tp=类型` + `k=序号` + `lat/lon/alt` + `t=时间戳`。

轨迹点类型（`tp` 取值，10 个样本实测）：

| `tp` | 含义 | key | value |
| --- | --- | --- | --- |
| `lbs` | 位置 | `k`=索引序号 | `lat`/`lon`（GCJ-02 度）、`alt`（米）、`t`（卫星时间） |
| `h-r` / `i-h-r` | 心率 / 瞬时心率 | 绝对毫秒时间戳 | 次/分 |
| `s-r` | 步频 | 绝对毫秒时间戳 | 步/分（**双脚**） |
| `alti` | 海拔 | 绝对毫秒时间戳（5 s 一点） | 米 |
| `rs` | 实时速度 | 相对 `startTime` 的秒偏移 | 分米/秒 |
| `cad` | 骑行踏频 | 绝对毫秒时间戳 | 转/分（仅骑行样本有） |
| `scp` | 跳绳瞬时频率 | 绝对毫秒时间戳（5 s 一点） | 次/分，未跳动的点为 0（仅跳绳有明细的 3 条记录里出现；当前跳绳样本是纯汇总记录，无此通道） |
| `spo2` | 血氧 | 绝对毫秒时间戳 | 百分比 |
| `p-m` / `b-p-m` | 公制 / 英制分段配速 | 编码值（序号×10000000 + 累计秒） | 秒/公里 |
| `sec` | 分段统计 | 无 `k`，用 `sn` 段序号标识 | 见下 |

`sec` 段内字段实测语义：`st` = 本段用时（**秒**）、`sd` = 本段距离（**厘米**）、`sp` = 配速、`shr` = 平均心率、`ssl` = 步长；`sc`、`str`、`std` 三个字段在样本中与任何已知指标都对不上，**语义未明，不可用**，转换时一律忽略。

### 3. 整段统计 `HW_EXT_TRACK_SIMPLIFY`

同在 `attribute` 字段中，`HW_EXT_TRACK_SIMPLIFY@is` 之后是一段完整 JSON，含设备端算好的**整段权威统计**：`avgHeartRate`/`maxHeartRate`/`minHeartRate`、`creepingWave`（累计爬升，分米）/`mTotalDescent`（累计下降，分米）、`mMinAlti`/`mMaxAlti`（米）、`avgStepRate`/`bestStepRate`、`avgPace`/`bestPace`、`partTimeMap`（公里刻度 → 累计净计时秒）、`paceMap`。这些值与华为 App 显示一致，**转换时应直接取用而非由轨迹点重算**。

统计块里还有两处必须特殊处理：

- `mExtendTrackDataMap`：各运动类型私有的扩展指标，value 一律是**字符串**。跳绳样本实测为 `{"interruptTimes":"2","skipSpeed":"149","skipNum":"1037","maxSkippingTimes":"382"}`，依次是中断次数、平均跳绳频率（次/分）、跳绳总个数、最大连跳次数。纯汇总的跳绳记录没有任何明细，这一个 map 就是全部的运动细节来源。
- `mMinAlti` / `mMaxAlti` 的**未采集哨兵**：无海拔数据时华为留下求极值的初值残留 —— `mMinAlti = 3.4028235E38`（`Float.MAX_VALUE`）、`mMaxAlti = 1.4E-45`（`Float.MIN_VALUE`）。判据是 `mMinAlti > mMaxAlti`，命中即视为无海拔数据，不可当真实海拔使用。

## 五、与样例数据的关系

- `input/sample/huawei/` 下放置**从原始数据抽取/转换出的单活动样例 JSON**（未随仓库发布）。
- `input/sample/garmin/` 下放置佳明侧真实 FIT 样例，作为字段对照基准（未随仓库发布）。
- 转换代码在 `src/main/java/me/frankhbu/fitconverter/`（Maven 工程，依赖 fastjson / Garmin FIT Java SDK）。
